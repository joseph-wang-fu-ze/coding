# 盲旋转 / SampleExtract 实测（路线 B，2026-09-19）

> 依据：CAPE 论文 §2 的 FHE 子程序定义。环参数：N=16384、t=65537、
> 声明 9 素数/438 位、**工作层 8 素数/389 位**、base=2¹⁶、levels=25。

---

## 一、论文定义（原文）

> **BlindRotate(ct_L, ct_R) → ct'_R**：给定 LWE 加密 `ct_L ← LWE.Enc_s(r)` 与累加器
> `P(X) = Σ_{i=0}^{N−1} p_i X^i` 的 RLWE 加密，按**加密下标 r** 同态旋转累加器，
> 使 **p_r 被移到 ct'_R 的常数系数**上。

> **SampleExtract_j(ct_R) → ct_L**：给定 `ct_R ← RLWE.Enc_s(Σ m_i X^i)`，取出第 j 个系数，
> 输出 `ct_L ← LWE.Enc_s(m_j)`；必要时包含到后续计算所用 LWE 密钥的密钥切换。

> **Pack({ct_L,i}) → {ct_R,β}**：把一批 LWE 密文的消息打包进一个或多个 RLWE 密文。
> **LWEtoRGSW(ct_L) → C_μ**：把 μ ∈ {0,1} 的 LWE 密文转成 RGSW（用于查询压缩变体的选择器扩展）。

## 二、实现方式

要的就是 `Q(X) = X^{−r}·P(X)`（常数项恰为 p_r），而

```
X^{−r} = X^{−b} · X^{⟨a,s⟩} = X^{−b} · Π_i X^{a_i·s_i}
```

于是：

```
ACC ← P(X) 的密文
对每个 i:  ACC ← CMUX(BK_i, ACC, ACC·X^{a_i})   // s_i=0 不动；s_i=1 乘 X^{a_i}
ACC ← ACC · X^{−b}                              // 公开量，不需要密钥
```

- `BK_i = RGSW(s_i)`，而 `s_i ∈ {0,1}` 正是 `encryptRgswConstant` 支持的常数选择器，
  所以**自举密钥直接可用**（`LWEtoRGSW` 那条后续也能复用同一构造）。
- `X^{a_i}` 与 `X^{−b}` 用新增的 `Mpc4jRgsw.multiplyPowerOfX`：负循环环里
  `k ≥ N` 等价位整体取负再平移 `k−N`，平移跨过 `X^N` 的项再变号，两个条件异或定符号。
- **LWE 模数取 `q_L = 2N`**：这样密文系数 `a_i` 本身就是旋转指数，无需缩放对齐
  ——这正是 CAPE 把 LWE 模数定成 2N 的原因。

## 三、实测结果

### 正确性（N=2048、d=64、q_L=4096）

| 项 | 值 |
|---|---|
| 自举密钥构造（64 个 RGSW，每个 8 密文） | 397 ms |
| 盲旋转（64 轮 CMUX + 1 次公开旋转） | 299 ms |
| **p_r 落到常数系数** | ✅ `r=1234`，常数系数 = 235 = p_1234 |
| **整条累加器与 X^{−r}P 一致的系数** | ✅ **2048/2048**（不只是常数项，整条都对） |

### 论文规模单步耗时与体积（N=16384）

| 项 | 实测 |
|---|---|
| 单个密文体积 | **1.00 MB**（8 素数 × 16384 × 8B） |
| 构造 1 个 RGSW | **1028 ms**，50 个密文，约 **50 MB** |
| 单次外部乘积 | **726 ms**（结果正确） |
| 单次公开旋转 X^k | **≈0 ms**（纯系数搬移） |
| 单次 CMUX | **688 ms**（1 次外部乘积 + 2 次加法） |

### 外推：一次盲旋转的成本（按 LWE 维数 d）

| d | 盲旋转耗时 | 自举密钥体积 |
|---|---|---|
| 64 | ≈ 44 s | ≈ 3.2 GB |
| 128 | ≈ 88 s | ≈ 6.4 GB |
| 256 | ≈ 176 s | ≈ 12.8 GB |
| 512 | ≈ 352 s | ≈ 25.6 GB |

## 四、真正的瓶颈是密钥体积，不是耗时

**50 MB × d** 的体积来自 `levels = 25`：底 B=2¹⁶ 受限于"数字必须以明文形式喂进
`multiplyPlain`"，而明文的 fast plain lift 窗口只有 `±t/2 = ±32768`（见 `Mpc4jRgsw.decompose`
的注释），所以 B ≤ t、层数被迫取到 `⌈389/16⌉ = 25`。

可选的收缩手段（都属于**参数/工程选择，不改论文算法**）：

| 手段 | levels | 每个 RGSW | 说明 |
|---|---|---|---|
| 现状：底 B=2¹⁶ | 25 | 50 MB | 受明文窗口约束 |
| **RNS gadget**：用 8 个素数的 RNS 分量当"数字" | **8** | ≈ 16 MB | 现代 RNS-RGSW 的标准做法（SEAL 自己的 key switching 就是这个） |
| RGSW 用独立上下文、放大明文模数（B 提到 2⁵⁹） | 7 | ≈ 14 MB | RGSW 的 gadget 常数不带 Δ 缩放，t 只需满足数字窗口 |
| 缩小 d | — | ∝ d | 论文**没有给 d**，这是我们必须自己定并记录在案的参数 |

另外注意论文原文：RGSW"用于盲旋转内部，以及查询压缩变体的选择器扩展"
（the query-compressed variants）——也就是说**RGSW 的大规模使用只出现在压缩变体**，
主流程未必需要 d 个 RGSW 位。
